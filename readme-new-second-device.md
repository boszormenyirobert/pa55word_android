Van egy kerdesem, de a kodot nem valtoztathatod meg. Ez  most csak exploration. A feladat egy implementacios tervet összetenni. Amennyiben egy mobil-telefon mar tul van a regisztracion akkor kepesnek kell arra lennie hogy egy masik telefonnak biztonsagos modon atadja a teljes konfiguracio-jat. Mivel mindket oldalon ugyan az az app fut, ezert az elkepzeles. Amelyik handy megakarja kapni az adatokat => ahhoz a handyn az appot nullarol teljesen elöröl kell installalni. Az installalas elsö lepese viszont a biometria utana szerintem egy opcio-t kene feldobni. "Private" or "Corporate". Most meg a mindig csak "Corporate" modban dolgozunk, mert a "Private" feature meg nincs implementalva. Tehat "Corporate" es utan ket lehetöseg van 1: Sync letez account (ez az uj funkcio) 2: New account registration(most ezzel indul az applikacio regisztracioja). Tehat az app funkciora most a sync-modot dolgozzuk ki. Ha a syncre kattint a felhasznalo, az azt jelenti, hogy "mi akarunk adatokat kapni". Ahhoz hogy biztonsagosan kapjunk adatokat, ahhoz kell egy private-public key generalas(ahogy korabban is ) es egy QR - code amely igy nez ki: {
  "type": "deviceSync",
  "deviceId": "...",
  "publicKey": "...",
  "deviceName": "..."
}. Utana a fogado oldal : kiolvassa a QR-code-ot es szerintem ugy arra az endpoint-ra kell elküldeni ugyan azt az adatstrukturat amelyet akkor keszitünk el amikor a QR-Code-ban   "type": "deviceRegistration",. van. Ahhoz hogy a "kero oldal" visszakapja a regisztracios adatokat, a kero a qr-kirajzolasa utan egybol indit egy regisztráció polling-ot. ( innen kell tovabb irni: melyik url, milyen header, es utana egy requesttel mar letudja kerni a sajat adatait)
