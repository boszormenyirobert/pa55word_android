# Local Storage

Purpose: exact description of what the app persists locally, where it is stored, and in what format.

## Persisted Storage Surfaces

1. Android Keystore
2. EncryptedSharedPreferences

No Room database, DataStore, flat-file JSON store, or custom SQLite store was found in the app code.

## Android Keystore

Location:
- Android system keystore under alias `secure_device_registration_primary`.

Stored material:
- One RSA keypair used for request signing and DEK decryption.

Format:
- RSA keypair generated by Android Keystore.
- Key size: `2048` bits.
- Signature algorithm used by the app: `SHA1withRSA`.
- Encryption padding support used by the app: `RSA/ECB/OAEPWithSHA-1AndMGF1Padding`.

Persistence behavior:
- The private key is non-exportable and remains inside Android Keystore.
- The public key is read from the keystore certificate and Base64-encoded when sent to the backend.
- If the alias does not exist, the app generates the keypair on demand.

## EncryptedSharedPreferences

Location:
- App-private `EncryptedSharedPreferences` file named `zero_intrusion_secure_registration`.

Encryption configuration:
- Key encryption: `AES256_SIV`.
- Value encryption: `AES256_GCM`.

Stored keys:
- `registration_state`
- `connected_devices_local_state`
- `recovery_pending_state`

### registration_state

Meaning:
- The current active phone registration and gateway namespace state.

Stored format:
- Single JSON object serialized from `RegistrationState`.

Shape:
```json
{
  "accountId": "string",
  "deviceId": "string",
  "deviceName": "string",
  "namespaceName": "string",
  "namespaceUrl": "string",
  "namespaceId": "string",
  "email": "string",
  "phone": "string",
  "encDek": "string|null",
  "root": true,
  "fcmToken": "string|null"
}
```

When written:
- Initial phone registration success.
- Successful recovery completion and local activation.
- Default namespace selection change in `Device Information`.
- FCM token synchronization when the token changes.

Field notes:
- `encDek` is the encrypted DEK ciphertext stored as a string.
- `root` marks the locally persisted phone registration as the root registration.
- `fcmToken` is optional and is filled after successful FCM token sync.

### connected_devices_local_state

Meaning:
- All locally known root-device to namespace connections used by the Connected devices view.

Stored format:
- JSON array serialized from a dedicated local connected-devices list.

Shape:
```json
[
  {
    "url": "string",
    "accountId": "string",
    "desktopDeviceId": "string",
    "namespaces": [
      {
        "accountId": "string",
        "desktopDeviceId": "string",
        "namespaceId": "string",
        "namespace": "string",
        "url": "string"
      }
    ]
  }
]
```

When written:
- Successful root-device registration flows.
- Connected-devices backend refresh after parsing account snapshots.

Merge rules:
- Entries are deduplicated by `namespaceId + namespaceUrl + deviceId` after trim and lowercase normalization.
- Stored list is sorted by `namespaceName`.

## What Is Not Persisted

The following state is in-memory only and is not written to local persistent storage:
- Live desktop sessions list.
- Connected-devices backend fetch results beyond the reduced persisted local list.
- Authentication notification overlay state.
- Desktop-session revoke progress state.
- Namespace delete confirmation UI state.
- Device-information dropdown pending selection UI state.

## Corruption Recovery

If encrypted preferences cannot be opened or decrypted after restore, reinstall, or key invalidation:
- The app deletes the entire `zero_intrusion_secure_registration` preferences file.
- It recreates the encrypted preferences file.
- `registration_state` is treated as missing.
- `connected_devices_local_state` falls back to an empty list.

The Android Keystore keypair is managed separately from the encrypted preferences file.

## recovery_pending_state

Meaning:
- Durable, protected checkpoint for a recovery that has received and decrypted
  its DEK but has not yet completed local activation.

When written:
- Before `POST /api/v1/recovery/completion`, after validating the candidate DEK
  response and decrypting its 32-byte DEK.

Contents:
- Recovery and candidate UUIDs, mobile device ID, approved API origin, current
  stage, expiration time, and the idempotent completion request ID.
- Account ID, email, phone, candidate public key, encrypted DEK, and returned
  namespace list.
- The pairing code and its hash are retained only inside this encrypted
  checkpoint so a candidate request can be retried with the same request ID
  after process death. They are never logged or copied to normal registration
  state. Signatures and raw plaintext DEKs are never persisted or logged.

Activation:
- After a successful completion response, the selected `root=true` namespace
  becomes `registration_state`.
- Every returned namespace is imported into the existing
  `connected_devices_local_state` representation so `NamespacesRepository`
  exposes the restored account's full namespace set.
- The pending state is deleted only after both local registration writes
  succeed. A failed or lost completion response leaves it available for an
  explicit same-request-ID retry.
